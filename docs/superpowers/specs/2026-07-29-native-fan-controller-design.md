# Native Fan Controller 재구축 설계

## 목표

Apple M2 Max MacBook Pro에서 온도와 팬 상태를 안정적으로 읽고, 사용자가 명시적으로 활성화했을 때만 팬 속도를 제어하는 네이티브 macOS 메뉴바 앱을 만든다.

첫 실행부터 다음 항목을 실제로 확인할 수 있어야 한다.

- 앱이 정상적인 macOS 앱 번들로 실행된다.
- CPU/GPU 온도, thermal pressure, 각 팬의 현재 RPM을 읽는다.
- 시스템 자동, 온도 곡선, 수동 고정 RPM 모드를 제공한다.
- 제어 실패, 앱 종료, 잠자기 전환 시 시스템 팬 제어로 복구한다.
- 외부 Python, Tkinter, `powermetrics`, `smc` CLI에 의존하지 않는다.

## 범위

### 포함

- SwiftUI 메뉴바 앱과 설정 창
- IOKit 기반 AppleSMC 읽기
- M2 Max의 두 팬 탐지와 실제/목표/최소/최대 RPM 읽기
- thermal pressure 읽기
- CPU/GPU 온도 센서 탐지와 최대 온도 계산
- 시스템 자동, 온도 곡선, 수동 고정 모드
- 관리자 인증을 거친 로컬 권한 컨트롤러
- 안전 복구와 sleep/wake 처리
- 설정 저장, 최근 10분 기록, 상태·오류 로그
- Swift 단위 테스트와 하드웨어 진단 모드
- 로컬 `.app` 번들과 설치 가능한 로컬 패키지

### 제외

- Mac App Store 배포
- 공인 서명 및 notarization
- M2 Max 이외 모델의 완전한 호환성 보장
- 0 RPM 또는 SMC 권장 최솟값 미만 설정
- 원격 제어, 계정, 클라우드 동기화

## 참고 구현

- `agoodkind/macos-smc-fan`: Apple Silicon SMC 구조, 모드 키 탐지, `Ftst` 처리, XPC 권한 경계
- `metaspartan/mactop`: M2 Max에서 확인된 SMC 읽기·쓰기와 팬 키
- `angristan/MacThrottle`: SwiftUI 메뉴바 UX, 센서 읽기, thermal pressure, 기록 그래프

참고 프로젝트는 모두 MIT 라이선스다. 직접 가져오는 코드가 있다면 저작권 고지와 라이선스를 배포물에 포함한다.

## 선택한 접근법

Swift 단일 코드베이스를 사용한다.

- 앱 UI와 상태 관리는 SwiftUI로 구현한다.
- SMC 통신은 IOKit을 직접 호출하는 Swift 모듈로 구현한다.
- 읽기 작업은 일반 사용자 권한의 앱에서 수행한다.
- 쓰기 작업은 관리자 인증 후 시작되는 별도 로컬 컨트롤러 프로세스에서 수행한다.
- UI와 컨트롤러는 로컬 IPC로 통신한다.

유료 Developer ID가 없으므로 공인된 `SMJobBless` 배포는 사용하지 않는다. 첫 버전은 로컬 전용이며 팬 제어 활성화 시 macOS 관리자 인증을 한 번 요청한다. 앱 종료 또는 재부팅 후에는 다시 인증한다.

## 아키텍처

### FanControllerApp

- 메뉴바 아이콘과 팝오버를 제공한다.
- 센서 상태, 팬 RPM, 제어 모드, 오류를 표시한다.
- 설정 창과 온도 곡선 편집 화면을 연다.
- 직접 SMC 쓰기를 수행하지 않는다.

### SMCKit

- `AppleSMC` IOKit 서비스를 연다.
- 키 정보, 데이터 크기, 데이터 형식을 확인한다.
- Apple Silicon의 4바이트 float와 정수 형식을 변환한다.
- `FNum`, `F0Ac`, `F1Ac`, `F0Mn`, `F0Mx`, `F0Tg` 계열을 읽는다.
- 모드 키 `F%dMd`와 `F%dmd`를 런타임에 탐지한다.

### SensorService

- M2 Pro/Max 계열 CPU/GPU 센서 키를 우선 탐지한다.
- 유효 범위의 센서만 사용하고 최대 온도를 대표 온도로 계산한다.
- SMC 온도 읽기가 실패하면 thermal pressure만 유지하고 팬 제어를 중지한다.
- 1초 간격으로 읽되 UI 갱신과 기록 저장은 분리한다.

### CurveEngine

- 온도 점 목록을 선형 보간해 목표 RPM을 계산한다.
- 히스테리시스와 상승/하강 제한으로 반복 변동을 줄인다.
- SMC가 보고한 최소·최대 RPM 범위 안에서만 값을 생성한다.
- 입력 누락, 비정상 온도, 오래된 센서 값에서는 목표를 생성하지 않는다.

### PrivilegedController

- 관리자 인증 이후 별도 프로세스로 시작한다.
- 허용된 IPC 명령만 받는다: 상태 조회, RPM 설정, 시스템 자동 복귀, 종료.
- SMC 키 이름을 클라이언트가 임의로 전달하지 못하게 한다.
- 주기적인 heartbeat가 끊기면 시스템 자동으로 복귀하고 종료한다.
- 한 팬만 실패해도 두 팬 모두 시스템 자동으로 복귀한다.

### SettingsStore

- 사용자 설정을 `Application Support` 아래 JSON 또는 `UserDefaults`에 저장한다.
- 온도 곡선, 마지막 표시 옵션, 기록 표시 여부를 저장한다.
- 실제 제어 모드는 앱 재시작 시 항상 시스템 자동으로 시작한다.

## UI 설계

MacThrottle과 같은 메뉴바 중심 구조를 사용한다.

### 메뉴바

- 현재 최대 온도와 상태 아이콘을 표시한다.
- nominal, elevated, hot, critical 상태를 색과 아이콘으로 구분한다.

### 팝오버

- 상단: 현재 온도, thermal pressure, 제어 모드
- 중단: Fan 1/Fan 2 실제 RPM과 목표 RPM
- 그래프: 최근 10분 온도와 팬 RPM
- 하단: 시스템 자동, 온도 곡선, 수동 고정 모드 선택
- 팬 제어 활성화 버튼은 관리자 인증과 안전 경고를 먼저 표시한다.

### 설정 창

- 온도 곡선 점 편집
- 수동 RPM 슬라이더
- 로그인 시 앱 실행
- 진단 결과와 최근 오류
- 시스템 자동 복귀 버튼

## 제어 흐름

1. 앱 실행 시 읽기 전용 진단을 수행한다.
2. 팬 개수, RPM 범위, 온도 센서를 확인한다.
3. 앱은 항상 시스템 자동 모드로 시작한다.
4. 사용자가 제어를 활성화하면 관리자 인증을 요청한다.
5. 권한 컨트롤러가 팬 모드 키를 탐지하고 저위험 제어 가능 여부를 확인한다.
6. 온도 곡선 또는 수동 모드에서 목표 RPM을 적용한다.
7. 앱과 컨트롤러가 heartbeat와 실제 RPM을 비교한다.
8. 종료, sleep, heartbeat 손실, 센서 실패 시 시스템 자동으로 복귀한다.
9. wake 후에는 자동으로 제어를 재개하지 않고 사용자 확인을 요구한다.

## 안전 정책

- 초기 허용 범위는 SMC가 보고한 최소 RPM 이상, 최대 RPM 이하로 제한한다.
- 온도 곡선은 온도가 높아질수록 RPM이 감소하지 않도록 검증한다.
- critical thermal pressure에서는 즉시 최대 권장 RPM을 요청한다.
- 온도 데이터가 5초 이상 갱신되지 않으면 시스템 자동으로 복귀한다.
- 목표 RPM 적용 후 실제 RPM이 일정 시간 반응하지 않으면 실패로 처리한다.
- 모든 정상·오류 종료 경로에서 시스템 자동 복귀를 시도한다.
- 하드웨어 쓰기 테스트는 한 번에 하나의 작은 변경만 수행하고 즉시 원복한다.

## 오류 처리

- 센서 읽기 실패: 제어 비활성화, thermal pressure만 표시
- 팬 탐지 실패: 모니터링 전용 모드
- 관리자 인증 취소: 읽기 전용 모드 유지
- SMC 쓰기 거부: 시스템 자동 복귀 후 원인 코드 표시
- IPC 연결 손실: 권한 컨트롤러가 자동 복귀 후 종료
- sleep/wake: sleep 전에 복귀, wake 후 재진단

## 검증 전략

### 자동 테스트

- SMC 데이터 형식 변환
- 온도 센서 값 필터링
- 온도 곡선 보간
- 히스테리시스와 RPM 변화 제한
- 비정상 설정 거부
- heartbeat 만료 시 자동 복귀 상태 전이
- sleep/wake 상태 전이

### 읽기 전용 하드웨어 진단

- `Mac14,6` 모델 확인
- AppleSMC 연결
- 팬 수와 각 팬 RPM 범위
- 실제 RPM
- CPU/GPU 온도 키
- thermal pressure

### 쓰기 하드웨어 검증

1. 현재 팬 상태를 기록한다.
2. 권장 최소 RPM보다 약간 높은 안전한 목표를 한 팬에 적용한다.
3. 실제 RPM 반응을 확인한다.
4. 즉시 시스템 자동으로 복귀한다.
5. 두 팬과 온도 곡선은 위 단계 성공 후에만 시험한다.

쓰기 검증은 사용자에게 위험과 변경 내용을 표시하고 명시적으로 승인받은 경우에만 수행한다.

## 빌드와 배포

- Swift Package Manager 기반으로 앱과 테스트 모듈을 구성한다.
- 프로젝트 로컬 `script/build_and_run.sh`가 빌드, 앱 번들 생성, 실행을 담당한다.
- 개발 빌드는 ad-hoc 서명을 사용한다.
- 최종 로컬 산출물은 `dist/FanController.app`과 설치 패키지다.
- 공인 서명이 없으므로 다른 Mac 배포와 Gatekeeper 자동 통과는 보장하지 않는다.

## 완료 기준

- 앱이 메뉴바에 나타나고 팝오버가 정상 표시된다.
- M2 Max의 온도와 두 팬 RPM이 1초 주기로 갱신된다.
- 읽기 전용 진단이 성공·실패 원인을 구체적으로 보여준다.
- 세 제어 모드가 UI에서 선택 가능하다.
- 관리자 인증 후 저위험 RPM 쓰기와 실제 RPM 변화가 확인된다.
- 모든 종료·오류·sleep 경로에서 시스템 자동 복귀가 확인된다.
- 새 `.app` 번들이 외부 Python 없이 실행된다.
